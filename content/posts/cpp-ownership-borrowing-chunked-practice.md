## 2. 练习 2：`get()`、移动和 `reset()`，不是三种“指针操作”那么简单

### 2.1 同样是不能编译，原因可能不同

我最初解释 `auto q = p` 失败时，把拷贝构造和 `explicit` 混在了一起，认为是不能进行隐式转换。

但这两行其实要分别看：

```cpp
auto p = std::make_unique<int[]>(1000);
// auto q = p;  // 错误：unique_ptr 的拷贝构造被删除

int* borrowed = p.get();
// std::unique_ptr<int[]> q = borrowed;
// 错误：这里的拷贝初始化不能使用相应的 explicit 构造函数
```

第一种情况下，两边已经是同一种智能指针类型，不需要把裸指针转换成智能指针；失败的关键是**不能复制独占所有者**。

接着我又问：

> “为什么 `std::unique_ptr<int[]> q(borrowed);` 这样能通过编译器……`()` 是怎么起作用的，强制类型转换？”

在这条变量声明中，`q(borrowed)` 是**直接初始化**，可以调用相应的 `explicit` 构造函数。但它会让 `q` 接管这个地址。如果 `p` 仍然拥有数组，就人为制造了两个所有者，最后可能重复释放。

所以，能编译只说明语法和类型规则允许；资源管理是否正确，还要看这个地址有没有其他所有者。

### 2.2 我对三个操作的第一版总结，还差了什么

我曾把它们总结成：`get()` 获得可读访问，`move()` 转移所有权，`reset()` 提前析构和释放。

方向接近，但每一句都需要更精确：

| 操作 | 准确含义 | 容易误会的地方 |
|---|---|---|
| `p.get()` | 返回当前保存的原始指针，不交出所有权 | 返回 `int*` 时可以修改数据，并不只读 |
| `auto q = std::move(p)` | `std::move` 提供可用于移动的表达式，`q` 的移动构造真正接管资源 | `std::move` 本身不搬数据、不执行释放 |
| `q.reset()` | 释放当前管理的资源，让 `q` 为空 | `q` 这个智能指针对象仍然存在 |

这与第一篇里“析构对象”和“释放资源”的区分接上了：**管理对象存在，不代表它一直持有资源；资源转交，也不代表源对象被销毁。** 智能指针的移动后状态与删除器调用规则，也可对照 [C++ 标准工作草案的构造说明](https://eel.is/c++draft/unique.ptr.single.ctor)和 [`reset` 说明](https://eel.is/c++draft/unique.ptr.single.modifiers)阅读；本文示例使用 C++17。

### 2.3 移动后，数组没搬家，借用也没有延长生命

```cpp
auto p = std::make_unique<int[]>(1000);
int* borrowed = p.get();
auto q = std::move(p);

assert(!p);
assert(q.get() == borrowed);
```

`q.get() == borrowed` 验证的是数组地址没有改变。移动的是管理责任，没有复制这 1000 个整数。

如果随后执行 `q.reset()`，数组被释放；`borrowed` 不会自动变成空指针，它已经悬空，不能继续解引用。可以把本地借用变量设为 `nullptr`，但这也不会替你更新其他地方保存的指针副本。

另一道追问是：移动后的 `p` 能否再使用？

```cpp
auto p = std::make_unique<int>(100);
auto q = std::move(p);
p = std::make_unique<int>(200);
// 此时 *p 为 200，*q 为 100
```

我判断可以，因为 `p` 没有被销毁。对 `unique_ptr` 来说，移动后源智能指针为空；但不能据此推断所有自定义类型移动后都会自动清空，源对象的状态取决于类型的约定和实现。

## 3. 练习 3：手写移动语义，暴露了我最容易混淆的地方

标准库帮我完成了资源转交以后，我开始用 `int* data_` 和 `std::size_t size_` 手写 `Buffer`。

这次最有价值的部分，是我反复写错的几行代码。

### 3.1 复制地址、清空指针、释放数组是三件事

第一版里我写过这些错误片段：

```cpp
// 错误片段，不可作为实现使用
this.data_ = other.data_;
other = nullptr;
```

`this` 是指向当前对象的指针，要用 `this->data_`；`other` 是 `Buffer` 对象的引用，要清空的是它的成员 `other.data_`，不是给整个 `Buffer` 赋 `nullptr`。

后来我又在接管资源后尝试删除源指针。这更危险：目标刚复制了同一个地址，若此时释放数组，目标保存的地址也随即失效。

最接近正确的版本里，我知道要“先释放旧资源”，实际却写成了：

```cpp
// 错误：仅清空成员，丢失了旧数组的地址
data_ = nullptr;
size_ = 0;
data_ = other.data_;
```

这里没有执行释放。如果当前对象原本有数组，又没有其他管理者保存它，旧数组就泄漏了。

现在我会把几种操作明确拆开：

| 语句 | 做了什么 |
|---|---|
| `data_ = other.data_` | 复制地址值；需要配合后续步骤实现所有权转交 |
| `other.data_ = nullptr` | 清空源对象的成员，不释放数组 |
| `delete[] data_` | 释放 `new[]` 分配的数组，不会自动把指针变量置空 |
| `other.size_ = 0` | 维护“空指针对应零长度”的类约定 |

### 3.2 移动构造和移动赋值，差别在目标是否已经存在

```cpp
Buffer(Buffer&& other) noexcept
    : data_(other.data_), size_(other.size_) {
    other.data_ = nullptr;
    other.size_ = 0;
}

Buffer& operator=(Buffer&& other) noexcept {
    if (this != &other) {
        delete[] data_;           // 目标已经存在，先释放旧数组
        data_ = other.data_;      // 接管源数组
        size_ = other.size_;
        other.data_ = nullptr;    // 源对象不再拥有它
        other.size_ = 0;
    }
    return *this;
}
```

移动构造正在创建新对象，没有本类已经持有的旧数组要清理，也没有返回值。移动赋值修改一个已经存在的对象，要先处理旧资源，通常返回 `Buffer&`。

我最初还在构造函数里写过 `return *this`，这也是把“创建对象”和“给已有对象赋值”混在了一起。

`this != &other` 是本练习的自移动保护：如果执行 `b = std::move(b)`，就保持当前状态。本类声明 `noexcept`，是因为这里的指针和长度转交、整数数组释放不会抛出异常；这个声明也让使用该类型的代码知道移动操作的异常约定。

这里再精确一点：`this` 是指针；**`*this` 是表示当前对象的左值表达式**。在 `return *this` 时，它绑定到返回类型 `Buffer&`，返回当前对象的引用。

手写裸指针类是为了看清规则。实际只需要连续整数存储时，`vector` 或由 `unique_ptr` 作为成员的封装，通常更容易正确管理资源。

### 3.3 `const int* data() const`，两个 `const` 限制不同的访问

我当时追问：

> “为什么说前一个 `const` 的作用是不允许通过返回的指针修改 `int`，怎么是修改 `int` 呢？”

这里的 `int` 是指针指向的整数对象。拆开读更清楚：

```cpp
const int* data() const;
// 返回 const int*：调用者不能通过这个指针修改整数
// 末尾 const：这是 const 成员函数，不能通过 this 修改普通数据成员
```

常见的成对接口是：

```cpp
int* data() { return data_; }
const int* data() const { return data_; }
```

需要注意，末尾的 `const` 不会自动让裸指针指向的整块数组变为只读。只读访问还要通过返回类型的 `const int*` 表达。这也不意味着没有其他可写别名；它只限制通过这个返回指针进行的访问。

## 4. 合并练习 4：类型一样，为什么仍然不能传 `p`？

这一轮把数组借用、引用和资源交接放进了同一个程序。我已经知道 `p` 的类型是 `std::unique_ptr<Payload>`，但面对这个函数还是卡住了：

```cpp
void consume(std::unique_ptr<Payload> owned);
```

我的疑问是：既然类型一致，直接 `consume(p)` 为什么不行？我还尝试直接传类型名 `std::unique_ptr<Payload>`，后来才想到 `std::move(p)`。

### 4.1 按值传参，也需要构造一个新对象

| 调用 | 参数如何接收 | 所有权的结果 |
|---|---|---|
| `add(*p)`，形参为 `Payload&` | 引用绑定原来的 `Payload` | 只借用，可以修改对象 |
| `read(*p)`，形参为 `const Payload&` | 只读引用绑定原对象 | 只借用 |
| `consume(p)`，形参按值接收智能指针 | 尝试用左值 `p` 拷贝构造 `owned` | 编译失败，拷贝被禁止 |
| `consume(std::move(p))` | 移动构造形参 `owned` | `owned` 接管，`p` 变空 |

`p` 本来就是正确类型，缺少的不是类型转换，而是**选择一种允许的方式构造形参**。

`std::unique_ptr<Payload>` 只是类型名；函数实参需要一个表达式。写 `std::unique_ptr<Payload>{}` 虽然构造了表达式，却是一个空智能指针，仍然没有交出 `p` 的资源。

### 4.2 声明中的 `&&`，也不意味着表达式一直是右值

在这次练习里，几个常用判断就足够帮助我读代码：

- `p` 是有名字的变量，表达式 `p` 是左值。
- `*p` 表示已有的 `Payload` 对象，也是左值，能绑定到 `Payload&`。
- `std::move(p)` 是将亡值表达式，允许移动构造形参。
- `Buffer&& other` 中，虽然形参类型是右值引用，函数体里有名字的表达式 `other` 仍是左值。

这时再读调用，就不会只盯着 `&`、`&&` 的字形猜行为。先看表达式，再看接收方要做什么，最后看谁负责释放。

运行修正后的合并练习，我反馈“完成修正测试通过了”，并确认 `p` 和 `owned` 是两个不同的智能指针对象。

整理版的输出是：

```text
sum=108
construct
after borrow: 15
inside consume
destruct
after consume
PASS
```

`destruct` 出现在 `after consume` 之前，说明被接管的 `Payload` 已在这次函数调用结束前被销毁。原来的裸指针借用不会自动清空，之后不能再通过它访问对象。

### 4.3 概念正确，算术仍然会写错

我把“每个元素增加 `delta`”写成了：

```cpp
// 错误：相当于 data[i] = 2 * data[i] + delta
data[i] += data[i] + delta;

// 正确
data[i] += delta;
```

这不是移动语义问题，是赋值表达式写错了。调试时要把“资源是否安全”和“计算是否正确”分别检查，不能因为刚学了复杂概念，就把所有错误都归因于它。

## 5. 练习 5：分块处理以后，为什么 `process` 没有移动？

这次的目标是把连续数组分成片段，每个元素恰好增加一次 `delta`，同时保持数组地址和所有权不变。

例如 `n = 10`、每块最多 4 个元素，区间依次是：

```text
[0, 4)  -> 4 个元素
[4, 8)  -> 4 个元素
[8, 10) -> 2 个元素
```

半开区间包含左端、不包含右端，长度就是两端之差。

### 5.1 一个失败的断言，暴露了我对指针传参的误解

我原来的代码是：

```cpp
int* process = owner.get();
add_chunked(process, n, chunk_size, 10);

// 错误预期：以为调用后 process 已到数组末尾
assert(owner.get() + n == process);
```

但函数签名是：

```cpp
void add_chunked(int* data, std::size_t n,
                 std::size_t chunk_size, int delta);
```

`data` 按值接收，是一个独立的指针变量，保存与 `process` 相同的地址。`owner` 则是管理数组的智能指针对象。

函数中的 `data + begin` 仅仅算出偏移地址，连局部变量 `data` 都没有修改。即使在函数里写 `data++`，改变的也只是局部副本。

但 `data[i] += delta` 修改的是它们共同指向的数组元素，调用者当然能看到。

因此，正确检查是：

```cpp
assert(owner.get() == process);
```

**地址相同，不意味着指针变量是同一个；指针变量不同，也不意味着数据被复制了。** `owner.get() + n` 表示尾后位置，可以作为有效数组范围的终点，不能解引用。

### 5.2 尾块长度和推进步长，要表达同一个处理范围

整理后的核心实现如下：

```cpp
void add_chunked(int* data, std::size_t n,
                 std::size_t chunk_size, int delta) {
    if (chunk_size == 0) {
        throw std::invalid_argument("chunk_size must be positive");
    }
    std::size_t begin = 0;
    while (begin < n) {
        const std::size_t len = std::min(chunk_size, n - begin);
        add_inplace(data + begin, len, delta);
        begin += len;
    }
}
```

这里的接口约定是：`chunk_size` 必须为正；`n > 0` 时，`data` 必须指向至少 `n` 个可写整数；`n == 0` 时允许传 `nullptr`。本练习使用小整数，增量计算也要保证不溢出 `int`。

我原来写的是 `begin += chunk_size`。对当时那几组小用例，它也能完成处理，并不是断言失败的原因。但使用实际处理长度 `len` 后，最后一步正好到达 `n`，也避免最后一次盲目加上过大块长。

还要单独拒绝零块长，否则非空数组会原地循环。

### 5.3 `size_t` 不只是“另一种 int”

我也问过：`std::size_t` 和 `int` 有什么区别，为什么创建指针总要用 `make_unique`，`std` 又是什么？

这些问题要拆开：

| 写法或类型 | 本练习中的作用 |
|---|---|
| `std` | 标准库的命名空间；`::` 用于限定其中的名字 |
| `std::size_t` | 无符号整数类型，用于数量、大小和下标；具体位宽依实现而定 |
| `int` | 有符号整数，这里用于数组值和可能为负的增量 |
| `int* p = &value` | 创建指向已有对象的指针，不申请动态数组 |
| `std::make_unique<int[]>(n)` | 创建动态数组并由 `unique_ptr` 管理 |

获取数组首地址也取决于持有者：`unique_ptr` 用 `.get()`，`vector` 和 `array` 可用 `.data()`，普通数组在相应表达式中可转换为首元素指针。借用 `.get()` 不会申请或复制数组。

另一个小坑来自这条原始求和断言：

```cpp
// n 是无符号数，n == 0 时 n - 1 会回绕
assert(total == n * (n - 1) / 2 + 10 * n);
```

对本练习的有限小规模用例，先转换再算更清楚：

```cpp
const long long count = static_cast<long long>(n);
assert(total == count * (count - 1) / 2 + 10 * count);
```

这不等于解决任意大输入的溢出问题；本练习只用下面这些小规模数据。

### 5.4 总和、逐元素和地址检查，各验证一件事

| `n` | 块长 | 覆盖场景 | 增加 10 后的总和 |
|---|---|---|---|
| 10 | 4 | 尾块不足 | 145 |
| 8 | 4 | 正好整除 | 108 |
| 3 | 8 | 块比数组大 | 33 |
| 5 | 1 | 每块一个元素 | 60 |
| 0 | 4 | 空区间 | 0 |

只看总和可能遗漏相互抵消的错误，因此还要逐元素断言 `owner[i] == i + 10`，确认每个元素的结果；地址断言验证借用没有改变起始地址。空区间测试则检查没有访问任何元素。

修正后，我反馈“已经改好并通过测试了”，并用自己的话解释：传参复制了一个指针，各自独立，但指向同一块内存。

## 6. 回看反复出现的问题，我需要怎样继续练

这几次最明显的现象是：我能用语言说出“先释放旧资源”，却在代码里写成 `data_ = nullptr`；能解释“移动构造”，却还没意识到按值传参也需要构造形参。

所以后续要练的不是继续背更多术语，而是让每一句解释都落到明确的状态变化上。

| 当时的误解 | 现在的检查方式 |
|---|---|
| 置空指针就释放了内存 | 找到实际调用的 `delete[]`、删除器或资源清理函数 |
| 指针地址相同就等于同一个对象 | 分开画出指针变量和被指向的数据 |
| 类型匹配就能按值传参 | 再看形参需要拷贝构造还是移动构造 |
| `std::move` 自动完成一切 | 找到真正接收它的移动构造或移动赋值 |
| 知道概念就代表代码没问题 | 同时检查语法、计算结果、边界和生命周期 |

现在每看到一行指针代码，我会先问：**改的是地址，还是地址处的数据？谁还拥有资源？借用什么时候失效？**

下一步适合继续做小型接口练习：先写函数签名，明确只读借用、可写借用或所有权转交；先预测对象状态和输出，再编译运行。对管理资源的类，持续覆盖移动构造、移动赋值、自移动和离开作用域几种路径。

这也在为 CUDA 打基础：以后显存分配与释放需要成对管理，线程或分块处理需要明确数据范围。不过这几次仍是 CPU 上的 C++17 练习，还没有验证 GPU 并行执行、同步或异步生命周期。
